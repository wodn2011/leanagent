# Blind Oracle Leak（盲注 oracle：二分逐位 + 线性页扫描）

## 第一原则（先读这条，避免 90% 的弯路）

**盲注从头到尾不"读"任何内存，不经过任何输出过滤逻辑。**
信号源是【参数检查的通过/拒绝】（错误消息 vs 正常响应），
不是读出的内容。输出过滤（仅可打印/遇 NUL 截断/遇非法字符退出等）
与盲注【完全无关】——它们只在参数检查【通过】后才会被调用。

★常见误区：花大量时间分析"怎么绕过输出过滤"——方向就错了。
你要找的不是"把指针读出来的方法"，而是"比较结果不同的两个
响应"。任何时候发现自己在分析输出过滤函数的绕过，立刻停下。

## 两个变体怎么选

| | 变体 A：二分逐位 | 变体 B：线性页扫描 |
|---|---|---|
| oracle 形态 | 边界比较的真假可区分（`offset < size`） | 访问有效页 vs 无效页的响应差异 |
| 已知条件 | 知道被探测值的【区间】（如 libc 指针范围） | 知道目标相对某锚点的【大致偏移】 |
| 查询次数 | ~48 次（每个地址） | ≤16 次粗扫 + 每级微调 |
| 典型场景 | 菜单堆题：view(idx, offset) 越界读 + 错误响应 | 负 size 下溢：程序把"距当前位置 -N 字节"当输入区 |

**判断依据**：能构造大小比较（二分问题）→ 变体 A；
只能构造"命中/不命中"（等值问题）→ 变体 B。

## 变体 A：二分逐位泄露

### 适用条件
- **核心原语**：RELATIVE_READ / 越界读（view/read 类操作能以【可控 offset】访问内存）
- **关键特征**：操作结果有【两种可区分的外部响应】——成功（有输出/继续运行）vs
  失败（"Invalid"/报错/退出/崩溃），且分支取决于被探测地址/字节

### 关键步骤
0. **选对信号源（决定 100 倍速度差）**：
   - 【优先】**进程内响应差异**：越界参数通常返回错误消息
     但【程序继续运行】——一次探测 = 几个 sendline + 一次 recv（毫秒级）；
   - 【仅当程序确实退出/崩溃才用】崩溃型 oracle：每次探测要重启进程
     + 重新布置堆 → 单次探测 ≥ 1s。写脚本前先试探一次：收到错误消息后
     再发一条菜单命令，能继续 = 进程内 oracle（多数程序的常态）。
1. **识别 oracle**：找"读操作的边界检查"——典型形式是
   `offset < obj->size` 或 `offset + length <= size`（unsigned、
   可整数回绕）。让被探测的指针落在参与比较的字段里
   （UAF/类型混淆把 size 覆盖成目标指针，是堆题的常用布置），
   则 `offset < size` 的真假 = offset 与指针的大小关系 =
   完整的二分 oracle
2. **确认响应可区分**：探测参数有效 vs 无效，观察输出差异。
   第二个参数（length 等）给 0 或同样越界的值，确保【绝不】进入
   真正的读取/打印路径
3. **构造二分**（对目标指针做区间收缩）：
   ```
   start = 0x00007f0000000000   # libc 指针典型区间
   end   = 0x00007fffffffffff
   while start != end:
       mid = (start + end + 1) / 2
       发送 view(idx, offset=mid)
       if 响应有效: start = mid     # 指针 >= mid
       else:        end = mid - 1   # 指针 < mid
   leak = start
   ```
   heap 指针区间同理（0x000055xxxxxxxxxx ~ 0x000056xxxxxxxxxx）

   ★I/O 纪律：每步 recv 带 timeout=2；二分前先用一次 oracle(0)
   （必真）/ oracle(区间上界)（必假）验证信号源，两问答案不符说明
   提示词同步有误，先修 I/O 再进二分循环。
4. **算基址**：`libc_base = leak - 已知偏移`（leak 的来源决定偏移）

## 变体 B：线性页扫描盲定位（+ stdin 缓冲区劫持）

### 适用条件
1. 程序有**可区分的交互响应**（某操作成功走 A 分支、失败走 B 分支——
   输出/超时/连接断开任一差异即可）；
2. 有一个**带符号/可传负数的尺寸或索引参数**（`size_t` 下溢 → 负值
   实际指向"距当前位置 -N 字节"的内存）；
3. 无直接输出泄露（不能 printf %p / view 内存）。

### 操作模板（从粗到细三级步进）
```python
base = -0xfde            # 起点偏移（按结构体布局估算：目标-已知锚点）
for i in range(15):      # 步进数 = 覆盖范围/页大小
    send(size = base); resp = recv()
    if b'Continue' not in resp: break   # 响应变了 = 命中
    base -= 0x1000       # 页粒度步进（4KB）
base -= 0x10             # 命中后小步微调（0x10/0x1 逐级）
```

要点：
- **响应差异要靠实测确认**：先各跑一次有效/无效地址，记录两种响应的
  稳定特征再写扫描循环，不要假设"没有输出 = 崩溃"；
- **扫描循环没有 break 会走过头**：命中后继续扫会跳过目标，响应变化即停；
- **微调阶段步子太大（直接 -0x1000 跳过目标字节）**：命中后必须降到
  0x10/0x1 粒度；
- `scanf %d` 读负数是合法输入——不要假设程序会拒绝负 size，
  实测下溢行为（`size_t` 语境下 -5214 可能被当巨值或负偏移）。

### 命中后的读取
定位到可控读起点后，用同样的负偏移让程序把 libc 内数据当输入读出：
`recvuntil(已知特征字节)` + 定长 `recv()` → u64 解出 libc 地址
（如 `_IO_default_finish` 的指针）→ **libc base = 泄露值 - sym 偏移**。

### stdin FILE 缓冲区劫持（ROP 上栈）
程序用 `fgets/scanf/getline` 读输入时，数据先进 stdin 的 `_IO_buf_base`
指向的缓冲区。若能改写 stdin 结构体里的缓冲区指针字段（或其邻近数据），
下一次读操作就会**把你的输入直接写到指针指向的位置**——指向栈上返回
地址附近 = 一次输入写入整条 ROP 链：
```python
# 已定位 stdin FILE 可写；用负偏移逐次微调逼近 _IO_buf_base 区域
for i in range(9):
    send('y'); send(size = base)
    base -= 1                      # 逐字节微调对齐
# 最终一次交互直接发送 ROP：
payload = b'n'*8 + flat(0, 0, ret, pop_rdi, binsh, system)
send(payload)                      # fgets 把 ROP 写进劫持后的缓冲区 = 栈
```
- 不需要伪造整个 FILE——只改**缓冲区指针**一个字段，风险最小；
- ROP 头部放垃圾填充对齐（`b'n'*8`）吸收 fgets 的行缓冲语义；
- 链尾经典三件套：`ret`（对齐）→ `pop rdi; ret` → `system`；
- 此路线**绕过栈 canary**（不是溢出覆盖，是程序自己把数据读上去）。
