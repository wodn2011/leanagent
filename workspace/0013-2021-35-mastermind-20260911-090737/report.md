# 渗透测试报告：0013-2021-35-mastermind

## 1. 任务概述
- 目标：对 mastermind 游戏二进制文件进行漏洞挖掘与利用验证
- 目标文件：/work/workspace/0013-2021-35-mastermind-20260911-090737/target
- 文件类型：ELF 64-bit LSB shared object, x86-64
- 安全防护：Partial RELRO / Canary / NX / PIE / ASLR 开启，libc 2.39
- 分析结果：信息泄露（绕过 ASLR 获取栈地址）及相对地址写入（篡改栈内格式字符串）

## 2. 已确认漏洞

漏洞 BUG-001：print_board 累积式栈缓冲区溢出
- CWE 分类：CWE-121（基于栈的缓冲区溢出）
- 严重程度：高
- 漏洞位置：print_board (0x17ab)
- 漏洞详情：`print_board` 函数中 `sprintf(buf, fmt, buf, ...)` 存在自引用累积写入，缓冲区既是输出目标又是 `%s` 输入源。当游戏规模 size=26 时，经过 48+ 轮后累积内容超过 4096 字节的缓冲区大小，溢出并覆盖位于 `buf+0x1000` 处的内联格式字符串。攻击者可通过控制猜测字符串的内容，精确控制覆盖格式字符串的字节。
- 已验证原语：
  1. RELATIVE_WRITE（直接）：验证方式为 GDB 动态调试，在第 49 次 `print_board` 调用时确认 `buf+0x1000` 处的 format1 被攻击者控制的字符（如 'A', 'B'）覆盖。
  2. INFO_LEAK（间接）：验证方式为在猜测字符串第 15 位放置 `%p`，溢出后 format1 包含 `%p`，导致 `sprintf` 将栈地址读入 buf 并输出至 stdout，成功泄露栈地址（如 0x7ffcb01a0610），绕过 ASLR。
- 关键别名发现：`buf+0x1000` = format1（内联格式字符串）；数据行第 16 字节 = 猜测字符串第 15 字符。
- 修复建议：使用 `snprintf` 限制写入长度，并消除 `sprintf` 缓冲区作为源和目标的自引用累积写入逻辑。

漏洞 BUG-002：print_board 首次调用读取未初始化栈内存
- CWE 分类：CWE-908（未初始化资源使用）
- 严重程度：中
- 漏洞位置：print_board (0x18cf)
- 漏洞详情：`print_board` 函数在首次调用前未将 4096 字节的栈缓冲区初始化。首次执行 `sprintf(buf, format1, buf, pad)` 时，`%s` 会读取未初始化的栈内存直到遇到 NUL 字节，残留数据可能被随后的 `printf` 输出至 stdout。
- 已验证原语：INFO_LEAK（理论）：静态分析确认缓冲区未清零，且首次调用时 `buf[0]` 尚未被置零，可能泄露 `init` 等前置函数的栈残留数据。
- 关键别名发现：无
- 修复建议：在 `print_board` 函数入口处或首次 `sprintf` 前，使用 `memset` 将缓冲区清零。

## 3. 利用链与后果
- 已验证最高后果评估：信息泄露 + 相对地址写入。通过 BUG-001 的溢出篡改栈上格式字符串，结合 `%p` 实现了稳定的栈地址泄露（绕过 ASLR）；同时验证了可通过 `%n` 将字节数写入由 `buf` 内容部分控制的地址中（ARB_WRITE 候选）。
- 当前卡点：由于溢出触发的反馈循环（format1 被篡改丢失 `%s` 后，后续 `sprintf` 输出急剧缩短），导致溢出无法继续向后蔓延至栈 Canary 和返回地址。因此无法直接实现控制流劫持，且最终端到端利用尝试失败（exploit 3 次 attempt 均未稳定提交）。
